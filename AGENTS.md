# Agents

This repo owns the Windows/WSL2 entry point and host-versus-Linux guidance. The shared Unix provisioning implementation currently lives in `groundwork-mac`; change managed files there instead of copying them here. Do not apply Linux home files to the Windows host or an Omarchy machine.

Engineering work follows Compass: start at `.compass/COMPASS.md`, with terms in `.compass/TERMINOLOGY.md`. Load `skills/reviewable-agent-workspaces/SKILL.md` before implementation or worktree changes, `skills/concurrent-agent-runtimes/SKILL.md` before starting or inspecting concurrent processes, and `skills/repeatable-agent-execution/SKILL.md` before the first edit in a checkout and before final proof. Selected skills, loaded from `skills/` when a task touches their area: `acceptance-evidence`, `accessible-product-development`, `agent-orchestration`, `ai-backend-change`, `ci-workflow-change`, `dependency-change`, `developer-tool-change`, `field-failure-backpressure`, `github-delivery-workflow`, `inclusive-content-design`, `inclusive-product-foundation`, `independent-code-review`, `internationalization-first`, `performance-sensitive-change`, `privacy-by-design`, `repo-contribution-etiquette`, `secure-by-design`, `shell-script-change`, `terminal-program-ux`, `testing-strategy`, `toolchain-authority`. GitHub writes follow `repo-contribution-etiquette` (act as the account that owns the repository).

Use [groundwork-core](https://github.com/jasondockery/groundwork-core) for shared operational docs and tailnet policy. The `core` submodule is pinned to a groundwork-core tag named in `.gitmodules`. `install-host-apps.ps1` reads `core/browser/brave.json` for Brave policies and the extension offer, and it does not keep a second copy. Keep original `groundwork` unchanged and available for curriculum and historical context.

Omarchy's keybindings and conventions are the target where they fit. T3 Code Nightly and Herdr must stay available inside WSL2, with providers authenticated there. Native Windows app installation and permissions are separate, explicit operations. Do not restore historical Groundwork shortcuts as the target.

Parse arguments before side effects. Help and invalid input must not mutate anything. Preserve Windows and WSL configuration, SSH credentials, Git identities, and old checkouts during migration. Test wrappers with isolated fixtures; never claim native Windows, WSL, desktop, or remote acceptance from a Linux-only fixture.

The commit identity guard is installed inside WSL2 from the `core` pin (v0.9.0, groundwork-core `docs/commit-identity.md`; docs in `docs/commit-identity.md`). `groundwork-commit-guard.py`, copied to `~/.local/lib/groundwork-windows` and run by `bootstrap.sh` before the engine apply, links `core/commit-guard/commit-identity-guard.sh` into `~/.config/groundwork/git-hooks` (never a copy), scopes `core.hooksPath` to repositories with an owned GitHub remote through `includeIf` in `~/.config/git/config` (never globally, git 2.36+, nothing written when a hooksPath is already set), forwards every hook to the repository's own, fills in Claude Code `attribution.commit` and `attribution.pr` as empty only where unset (numbered backup), and creates an empty denylist when missing. Never write a name, an organization, or a denylist value into this repo. Never run it on the Windows host. `groundwork-commit-guard off` is the opt-out; `doctor` reports.
